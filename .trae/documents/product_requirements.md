## 1. 产品概述

会议室设备报修台——让投影打不开、麦克风没声、白板笔没墨不再靠群里喊。员工可快速报修设备故障，维修人员高效接单处理，管理员掌握全局统计。
- 解决传统微信群/口头报修的混乱遗漏、无追踪、响应慢问题
- 面向企业行政和IT运维团队，提升会议室设备维修效率和会议体验

## 2. 核心功能

### 2.1 用户角色

| 角色 | 说明 | 核心权限 |
|------|------|----------|
| 普通员工 | 日常使用会议室的员工 | 登记会议室、提交报修、查看替代建议 |
| 维修人员 | IT/行政维修团队 | 接单、记录处理过程、标记恢复时间 |
| 管理员 | 行政主管/IT主管 | 查看统计、管理会议室、采购决策 |

### 2.2 功能模块

1. **报修看板页**：按状态分列展示工单，紧急优先排序
2. **会议室登记页**：录入会议室基本信息与设备清单
3. **报修提交页**：填写故障详情、上传照片、标记紧急程度
4. **工单处理页**：维修人员接单、记录原因与方案、预估恢复时间
5. **替代建议页**：推荐可用替代会议室
6. **统计概览页**：问题频次、修复时长、设备故障排行

## 3. 核心流程

员工发现设备故障 → 提交报修工单（选设备、描述故障、标记紧急程度、上传照片、填写影响会议时间） → 工单进入"待处理"列 → 维修人员接单 → 工单进入"维修中" → 维修人员记录故障原因、处理办法、是否需要外部供应商、预计恢复时间 → 如需采购则移入"需采购"列 → 修复完成标记"已修好" → 系统自动推荐替代会议室给受影响的会议

```mermaid

    "发现设备故障" --> "提交报修工单"
    "提交报修工单" --> "工单进入待处理"
    "工单进入待处理" --> "维修人员接单"
    "维修人员接单" --> "工单进入维修中"
    "工单进入维修中" --> "记录处理过程"
    "记录处理过程" --> "是否需要采购"
    "是否需要采购" --> "是" --> "移入需采购列"
    "是否需要采购" --> "否" --> "修复完成"
    "移入需采购列" --> "采购到货"
    "采购到货" --> "修复完成"
    "修复完成" --> "工单进入已修好"
    "工单进入待处理" --> "系统推荐替代会议室"
```

## 4. 用户界面设计

### 4.1 设计风格

- 主色调：深蓝灰（#1E293B）+ 琥珀警示橙（#F59E0B）+ 翠绿完成色（#10B981）
- 辅助色：石板灰（#64748B）、浅灰底（#F8FAFC）
- 按钮风格：圆角8px，轻微阴影，hover微升效果
- 字体：Noto Sans SC（正文）+ DM Sans（数字/英文标题）
- 布局风格：顶部导航 + 左侧子导航，卡片式内容区
- 图标风格：Lucide线性图标，2px描边
- 紧急标识：脉冲动画红点 + 倒计时文字

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI元素 |
|----------|----------|--------|
| 报修看板页 | 状态看板 | 四列看板布局，每列顶部状态标签+计数，工单卡片含会议室名、设备、故障、紧急标识 |
| 报修看板页 | 紧急排序 | 卡片左边缘彩色条（红=紧急/橙=较急/灰=一般），紧急卡片带脉冲动画 |
| 会议室登记页 | 表单 | 分组表单，设备清单用Tag式多选，底部操作栏固定 |
| 报修提交页 | 表单 | 步骤指示器，故障现象用可展开Tag选择，照片上传用拖拽区域 |
| 工单处理页 | 详情面板 | 右侧抽屉式面板，顶部工单摘要，中间处理表单，底部操作按钮 |
| 替代建议页 | 会议室卡片 | 横向滚动卡片，显示会议室名、楼层、容量、可用设备标签、空闲时段 |
| 统计概览页 | 图表区 | 顶部三个指标卡，下方柱状图+饼图+趋势线 |

### 4.3 响应式设计

- 桌面优先设计，1920px/1440px为主要断点
- 平板端看板列改为水平滚动
- 移动端看板列改为Tab切换

### 4.4 动效设计

- 工单卡片：hover时微微上浮+阴影加深
- 状态变更：卡片从一列飞到另一列的过渡动画
- 紧急工单：左侧红色脉冲条 + 缓慢呼吸效果
- 接单按钮：点击后涟漪效果 + 状态即时切换
- 页面切换：淡入+微上移
